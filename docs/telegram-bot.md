# Telegram: ежедневный отчёт по продажам

Бэкенд может **каждый день в заданное время** (по умолчанию **21:00**) отправлять в Telegram сводку:

- выручка за календарный день;
- оценка прибыли (по текущим закупочным ценам товаров в базе);
- число чеков и суммарное количество проданных штук;
- топ товаров по количеству.

## Безопасность

- **Токен бота** (`TELEGRAM_BOT_TOKEN`) и **chat_id** нельзя светить в чатах, Git и скриншотах — только в `backend/.env` на сервере (файл не коммитится).
- Имя бота в Telegram (например `@foziljonavtozapchasti_bot`) можно писать открыто; **секретный токен** выдаёт только @BotFather.

## 1. Токен

1. В Telegram откройте [@BotFather](https://t.me/BotFather).
2. `/newbot` или используйте уже созданного бота.
3. Скопируйте токен вида `123456789:AAH...` в переменную **`TELEGRAM_BOT_TOKEN`**.

## 2. Chat ID (куда слать)

1. Найдите своего бота в Telegram и нажмите **«Запустить»** / отправьте **`/start`**.
2. На сервере (или с ПК, подставив свой токен):

```bash
curl -s "https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates" | head -c 2000
```

3. В ответе найдите `"chat":{"id":123456789` — это **`TELEGRAM_CHAT_ID`** (число, иногда отрицательное для групп).

Несколько получателей: перечислите id через запятую в одной переменной:

`TELEGRAM_CHAT_ID=111111111,222222222`

## 3. Переменные окружения (`backend/.env`)

| Переменная | Обязательно | Описание |
|------------|-------------|----------|
| `TELEGRAM_BOT_TOKEN` | да | Токен от @BotFather |
| `TELEGRAM_CHAT_ID` | да | Кому слать (один или несколько через `,`) |
| `TELEGRAM_REPORT_TZ` | нет | Часовой пояс для «дня» отчёта (по умолчанию `Asia/Almaty`) |
| `TELEGRAM_REPORT_HOUR` | нет | Час отправки, 0–23 (по умолчанию `21`) |
| `TELEGRAM_REPORT_MINUTE` | нет | Минута (по умолчанию `0`) |
| `TELEGRAM_DAILY_REPORT` | нет | `false` — отключить задачу, не удаляя токен |

После изменения `.env` перезапустите контейнер бэкенда:

```bash
docker compose --env-file .env.vps -f docker-compose.vps.yml up -d --build backend
```

(или ваш способ перезапуска `skladpro-backend`.)

## 4. Примечания

- **Прибыль** считается как `(цена продажи − текущая закупка) × шт` по каждой строке чека. Если закупку потом меняли в каталоге, цифра за прошлые дни исторически не «заморожена» — это оценка по текущим данным.
- Время срабатывания — **по выбранному часовому поясу** (`TELEGRAM_REPORT_TZ`), не по UTC.
- Планировщик встроен в процесс **одного** воркера uvicorn в контейнере `backend`; при масштабировании на несколько воркеров отчёт может продублироваться — для такого режима лучше вынести cron на хост.
