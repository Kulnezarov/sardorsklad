# Telegram: ежедневный отчёт по продажам

Бэкенд может **каждый день в заданное время** (по умолчанию **21:00**) отправлять в Telegram сводку:

- выручка за календарный день;
- оценка прибыли (по текущим закупочным ценам товаров в базе);
- число чеков и суммарное количество проданных штук;
- топ товаров по количеству.

## Безопасность

- **Токен бота** (`TELEGRAM_BOT_TOKEN`) и **chat_id** нельзя светить в чатах, Git и скриншотах — только в `backend/.env` на сервере (файл не коммитится).
- Имя бота в Telegram (например `@foziljonavtozapchasti_bot`) можно писать открыто; **секретный токен** выдаёт только @BotFather.

## 1. Токен

1. В Telegram откройте [@BotFather](https://t.me/BotFather).
2. `/newbot` или используйте уже созданного бота.
3. Скопируйте токен вида `123456789:AAH...` в переменную **`TELEGRAM_BOT_TOKEN`**.

## 2. Chat ID (куда слать)

1. Найдите своего бота в Telegram и нажмите **«Запустить»** / отправьте **`/start`**.
2. На сервере (или с ПК, подставив свой токен):

```bash
curl -s "https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates" | head -c 2000
```

3. В ответе найдите `"chat":{"id":123456789` — это **`TELEGRAM_CHAT_ID`** (число, иногда отрицательное для групп).

Несколько получателей: перечислите id через запятую в одной переменной:

`TELEGRAM_CHAT_ID=111111111,222222222`

## 3. Как выглядит `.env` (пример)

Файл: **`backend/.env`** на сервере (в репозиторий не коммитить).

```env
# Токен от @BotFather — одна строка, цифры:буквы (НЕ username бота!)
TELEGRAM_BOT_TOKEN=7123456789:AAHxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

# Ваш chat id — только цифры (может быть отрицательным для группы)
# Это НЕ @foziljonavtozapchasti_bot и НЕ «id бота»
TELEGRAM_CHAT_ID=123456789

# Несколько чатов:
# TELEGRAM_CHAT_ID=111111111,-1001234567890

TELEGRAM_REPORT_TZ=Asia/Tashkent
TELEGRAM_REPORT_HOUR=21
TELEGRAM_REPORT_MINUTE=0

# Команды в чате (/категории, /поиск …) — по умолчанию включены
# TELEGRAM_COMMANDS=false

# Ежедневный автоотчёт в 21:00 — по умолчанию включён
# TELEGRAM_DAILY_REPORT=false
```

**Не путать:**

| Что | Пример | Куда в `.env` |
|-----|--------|----------------|
| **Токен бота** | `7123456789:AAH...` | `TELEGRAM_BOT_TOKEN` |
| **Username бота** | `@foziljonavtozapchasti_bot` | никуда (для людей, чтобы найти бота в поиске) |
| **Ваш chat id** | `123456789` | `TELEGRAM_CHAT_ID` |
| **ID бота** (числовой) | редко нужен | обычно **не** вписывают |

## 4. Команды бота в Telegram (склад)

После перезапуска `backend` бот **сам опрашивает** Telegram (long polling). Отвечает **только** чатам из `TELEGRAM_CHAT_ID`.

Напишите боту в личку:

- **`/start`** — приветствие и **кнопки меню** под полем ввода  
- **`/help`** — текстовые команды  

Кнопки:

- **Категории склада** — остатки по категориям (только просмотр)  
- **Поиск по складу** — затем одним сообщением запрос; в ответе **закуп ₸** и **кол-во** (редактировать склад нельзя)  
- **Нужно заказать** — позиции `wish_items` со статусом *pending* (ещё не «заказано»)  
- **Добавить в список** — затем название детали → новая строка в «нужно заказать»  
- **Отчёт за сегодня** — как вечерний отчёт  
- **Заказано / в пути** — `purchase_orders` со статусами *in_transit* / *partial*  

Команды-аналоги: `/кат …`, `/поиск …`, `/заказать Название`, `/отчет`, `/отмена`.

Так можно **сразу проверить**, что бот живой, без ожидания 21:00.

## 5. Таблица переменных

| Переменная | Обязательно | Описание |
|------------|-------------|----------|
| `TELEGRAM_BOT_TOKEN` | да | Токен от @BotFather |
| `TELEGRAM_CHAT_ID` | да | Кому слать и кто может пользоваться командами (через `,`) |
| `TELEGRAM_REPORT_TZ` | нет | Часовой пояс для «дня» отчёта (по умолчанию `Asia/Almaty`) |
| `TELEGRAM_REPORT_HOUR` | нет | Час отправки, 0–23 (по умолчанию `21`) |
| `TELEGRAM_REPORT_MINUTE` | нет | Минута (по умолчанию `0`) |
| `TELEGRAM_DAILY_REPORT` | нет | `false` — отключить вечерний автоотчёт |
| `TELEGRAM_COMMANDS` | нет | `false` — отключить long polling и команды в чате |

После изменения `.env` перезапустите контейнер бэкенда:

```bash
docker compose --env-file .env.vps -f docker-compose.vps.yml up -d --build backend
```

(или ваш способ перезапуска `skladpro-backend`.)

## Проверка без ожидания до 21:00

Автоматическое сообщение уходит **один раз в день** в заданное время. Чтобы сразу проверить токен и chat id:

1. Войдите в склад в браузере, откройте DevTools → Network, выполните любой запрос к API и скопируйте заголовок `Authorization: Bearer …`  
   либо получите токен через `POST /api/v1/auth/login`.

2. Выполните (подставьте свой URL и токен):

```bash
curl -s -X POST "https://ВАШ_ДОМЕН_ИЛИ_IP/api/v1/settings/telegram/test" \
  -H "Authorization: Bearer ВАШ_JWT_ТОКЕН" \
  -H "Content-Type: application/json"
```

Ответ `{"ok":true,...}` — в Telegram должно прийти тестовое сообщение. Ошибка `400` — не заданы переменные в `.env` контейнера. `502` — неверный токен/chat_id или сеть; смотрите `docker logs skladpro-backend`.

3. В логах при старте бэкенда должна быть строка про планировщик, например:  
   `Telegram: планировщик — каждый день в 21:00 (Asia/Tashkent)`.  
   Если её нет — нет `TELEGRAM_BOT_TOKEN` или `TELEGRAM_CHAT_ID`, либо старый образ без кода Telegram.

## 6. Примечания

- **Прибыль** считается как `(цена продажи − текущая закупка) × шт` по каждой строке чека. Если закупку потом меняли в каталоге, цифра за прошлые дни исторически не «заморожена» — это оценка по текущим данным.
- Время срабатывания — **по выбранному часовому поясу** (`TELEGRAM_REPORT_TZ`), не по UTC.
- Планировщик встроен в процесс **одного** воркера uvicorn в контейнере `backend`; при масштабировании на несколько воркеров отчёт может продублироваться — для такого режима лучше вынести cron на хост.
